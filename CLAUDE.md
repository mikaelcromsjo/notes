# CLAUDE.md

Personal notes app: notes are a link graph, rendered as a 3x3 grid around one centered note. Express + better-sqlite3 (`server/`), no-build vanilla-JS IIFE (`public/`). No bundler, no tests, no lint.

This checkout (`/srv/notes`, port **8050**) serves **notes.ia-ai.se**. It was forked from `/srv/nico-server` (port 8040, **test.ia-ai.se**) on 2026-09-15 — same codebase, independent data from that point on (no sync between the two). Keep both running; `test.ia-ai.se` stays as-is.

`notes-android/` is a sub-project in this same git repo: a native Android WebView wrapper (`se.iaai.notes`) plus two home-screen widgets and native reminder-polling, all built against whichever `base_url` (currently notes.ia-ai.se) is baked into it — see `notes-android/CLAUDE.md`. It has its own Gradle build, unrelated to `npm`/`server/`.

## Run

- `npm start` (= `node server/index.js`). `npm install` for deps.
- Env: read from gitignored `.env` at the repo root (`process.loadEnvFile` at the top of `index.js`; real env vars win) — here `PORT=8050`, `PUBLIC_ORIGIN=https://notes.ia-ai.se`. Vars: `PORT` (**8050** here), `HOST` (127.0.0.1), `DB_PATH` (sqlite file, for testing on a copy), `SEED_USER_EMAIL`, `PUBLIC_ORIGIN` (link base for widget/digest/auth/account links; request routes fall back to forwarded headers, the schedulers to `http://127.0.0.1:PORT` — so set it or digest push/email links are unusable), `VAPID_CONTACT`.
- **Restart after any `server/` change** — code and `db.js` migrations only load on boot. `public/` static, no restart — but `sw.js` precaches the shell (stale-while-revalidate), so a `public/` change lands on the **2nd** load; bump `CACHE_VERSION` to purge.
- A PostToolUse hook in `.claude/settings.local.json` (gitignored, per-machine) auto-restarts the bare `node server/index.js` after any `server/**` edit, logging to `data/server.log`.
- A bare `node server/index.js` is usually already running (no systemd). Check `ps aux | grep server/index.js` before a 2nd instance — WAL lock clash.

## Gotchas

- `data/notes.db` is the **only copy of real user data**. Never rm/reset it. To test server logic, `Database(src).backup(dest)` and run with `DB_PATH` on another `PORT`.
- Multi-user: opaque `nico_sess` cookie → `sessions` row → `req.userId`/`req.sessionId` (see `server/sessions.js`); every route scopes by `req.userId`. Session created on email login (`POST /api/session`), destroyed on `DELETE /api/session`. The legacy raw-id `nico_uid` cookie is auto-upgraded to a session by the `/api` middleware in `index.js` (migration shim — remove after users have migrated). `COOKIE_INSECURE=1` drops the `Secure` flag for local HTTP testing. `data/` + `node_modules/` gitignored.
- Exception to the cookie gate: `/api/widget?token=` and `/digest?token=` are token-authed, mounted **above** it in `index.js`. Token in `users.widget_token`, minted lazily by `server/widget-token.js` `ensureWidgetToken()` (used by `GET /api/session` and the digest link builders), rotate/revoke via `POST`/`DELETE /api/session/widget-token`.
- Schema changes: idempotent `PRAGMA table_info` + `ALTER TABLE` in `db.js`, not `CREATE TABLE` edits.
- `GET /api/notes/:id/neighbors` returns `{ parent, neighbors }` (not an array). `neighbors` ranked by `nav_events` history (`SCORE_W`/`HALF_LIFE_DAYS` in `notes.js`); cold-start = link recency. `parent` = probable back-link. `GET /api/links` = whole link graph, mirrored to IndexedDB for offline neighbour recompute (link-recency = cold-start).
- **Offline (PWA).** `public/store.js` = IndexedDB wrapper (stores `notes`/`links`/`outbox`/`blobs`/`meta`/`neighbors`/`assets`, DB **v3**). Reads write-through; fall back to the mirror on fetch failure; SW-cached shell boots offline. Offline (or mid-request-drop) writes = optimistic + `outbox`, replayed in order by `flushOutbox()` on reconnect / 30 s tick / `visibilitychange`. Offline-created rows get a `tmp:`/`rtmp:` id → real on create-sync (`remapId`/`remapReminderId`). Reminders mirror whole in `meta['alarms']`. 4xx → topbar pill → sync panel (Retry/Discard); network/5xx → retry.
- **Grid coherence offline.** `getNeighbors` caches the server-ranked `{ parent, neighbors, links }` per note (`.p`/`.score` kept) in the `neighbors` store; offline serves that blob (deleted-filtered vs `allNotesCache`; `cache.patchNeighborLink` fixes it on offline link/unlink) → cell order + path-heat = last online visit; never-visited → link-recency. `note-heat`/`insights` cached in `meta` (`cachedStat`) → colour modes keep tints offline.
- **Warm cache (phase 5).** The list endpoint (`GET /api/notes`) omits `content`/`attachment_path` to stay light, so historically only an individually-opened note had them mirrored — offline, a never-opened note showed literal `"undefined"` in the editor (and risked autosaving that over the real text once back online). `warmCache()` (called from `init()` and `reconnect()`, never awaited by rendering) now pulls `GET /api/notes/full` (`{id, content, attachment_path, updated_at}` for every note — text is cheap even at thousands of notes, so no budget) and merges it via `cache.mergeFullNotes` (same "skip a `_dirty` note" rule as `mergeNotes`). Where content is still genuinely uncached (a note created elsewhere since this device's last successful warm cache), `buildNoteEditor`/`makeCenterCell` show "Not available offline" and disable that note's title/text editing (`currentNote.content == null` is the tell — the server never returns `undefined`, only `''`) rather than risk clobbering it. Attachment *files* are a separate, budgeted download: `warmAttachmentCache()` walks `GET /api/notes/attachments-manifest` (image/audio/file notes only, newest-`updated_at`-first, with `notes.attachment_size` — backfilled lazily by that route via `fs.statSync` for rows uploaded before the column existed) and downloads into the `assets` store up to `assetCacheBudget()`: an environment baseline (Android+installed 500MB / Android browser tab 150MB / iOS installed 200MB / iOS browser tab 50MB / desktop 500MB — installed PWAs get Chrome's automatic persistent-storage grant and a real quota that large, a bare tab can vanish on uninstall/clear, iOS Safari purges unused tab storage after 7 days) clamped to half of `navigator.storage.estimate()`'s headroom. `meta['assetIndex']` tracks `{size, updatedAt}` per cached path so budget/eviction math never loads blobs into memory; anything no longer in the manifest or pushed past the budget line by newer attachments is evicted. `resolveMediaUrl` serves straight from the network when online (unchanged) and only consults `assets` offline; a miss renders `mediaUnavailableNotice()` ("📵/🖼/🔊 Not available offline") instead of a broken image/audio player or dead download link.
- **Themes** (🖌️ header button → `#theme-overlay`, tabs App / This note). `public/themes.js` is the single model, a UMD file loaded by the browser (`window.NicoThemes`, in `<head>` so `boot()` pre-paints the cached colours) **and** `require`d by the server (`../public/themes.js`) — `sanitizeStyle` whitelists every value (hex colours, font key, `preset:<key>`|`/uploads/<file>`|`none` images, hue 0-359, dim 0-90, glow 0-100, `cardAlpha` 0-100 = card background opacity, shown in the editor as "Transparency" = 100 − alpha, applied via `--card-alpha` in `.cell`'s `color-mix` + the card image layers, `textFx` `auto|off|shadow|outline` → `--text-shadow` on `.cell`: a halo in the opposite tone to the text colour, `auto` only over a card image with dim < 50 or a translucent card over a page image — see `textShadow()`) since it ends up in inline CSS — **the server `require`s this file, so a `themes.js` change needs a server restart** (the hook only fires on `server/**` edits, and an old process silently drops fields it doesn't know); Colours cover the whole UI, not just the reading surface — `COLOR_GROUPS` = Core (`bg`/`surface`/`text`/`accent`/`border`) + Tabs & status (`pin`/`todo`/`waiting`/`latest`/`noteHeat`/`alarm`/`danger`, i.e. the pin/todo/waiting/latest/alarm header bars, the note-heat colour-coding tint, and delete/danger buttons), `COLOR_KEYS` is both flattened; every key in `AUTO_CONTRAST_KEYS` (`accent` + all seven tab/status ones) gets its own auto-computed `--<name>-contrast` (light or dark text, whichever reads) the same way `accent-contrast` always worked — `effectiveColors`/`cssVars` compute all of it, the theme editor's colour rows are just `COLOR_GROUPS` rendered generically, so a new colour key needs no editor-UI change. 11 built-in presets (`PRESETS`): Light/Dark/Neon plus 8 more (Sunset/Ocean/Aurora/Forest/Rose Quartz/Slate/Sepia/Midnight — 4 pair a colour palette with a built-in background image, 4 are flat colour). `cssVars` maps a style to CSS custom properties (`--bg/--surface/--text/--accent/--border/--muted` + the seven tab/status colours and their `-contrast` pairs, `--font-body`, `--bg-*`/`--card-*` `img|hue|dim`, `--shadow` glow). A *style* is sparse — absent = inherit — and `mergeStyles` merges field by field. Fonts are vendored woff2 in `public/vendor/fonts/` (`@font-face` in `style.css`, precached by `sw.js`, OFL — see `LICENSES.txt`); preset images are pure CSS gradients so the hue slider is just `filter: hue-rotate` on a `::before` layer (`.theme-bg` for the page, `.cell.has-card-img` for cards). Two stores: account **app theme** = `users.theme_prefs` JSON `{active, custom[]}` (`GET`/`PUT /api/theme`; client keeps it in localStorage `nico-theme-prefs-<uid>` with a `dirty` flag, `syncThemePrefs()` on boot/reconnect/edit, local dirty wins) and per-note `notes.theme` JSON + `theme_children` (`PUT /api/notes/:id/theme` → `api.setNoteTheme`, outbox kind `note.theme`, deliberately does **not** bump `updated_at` and is not in undo history; the list route carries both columns). Effective style = app theme ← ancestors with `theme_children` (root first) ← the note's own (`styleFor` in `app.js`); "ancestors" = the **server's** inferred hierarchy via `GET /api/notes/hierarchy-parents` (fetched per `render()` only while some note cascades, mirrored in `meta['hierarchyParents']` for offline — the local rebuild can't see `created_from_note_id`). Two scopes (`applyScreenTheme`): the **app theme** styles the chrome (header, bars, dialogs) as vars on `<html>`; the centered note's resolved style is applied only as inline vars on `#grid`, `#note-overlay` (the editor) and `.theme-bg` (page background), so a note theme never touches the header or its font. Every cell gets its own note's vars inline only when they differ from the grid's (`applyCellTheme`); live edits re-style in place via `restyleAll()` (no full render). Uploads: `POST /api/theme/image` (client downsizes to 1600px JPEG first; MIME allowlist, 8 MB, recorded in `theme_images`; a theme may only reference the user's own; `sweepImages` deletes unreferenced ones after a 1 h grace on each theme save). Offline, uploaded images come from the `assets` store as object URLs (`warmThemeImages()`, `prepareOfflineThemeImages()`) — not in `assetIndex`, so attachment eviction never touches them. Editing a built-in theme forks it into a custom one.
- `PUT /api/notes/:id` + optional `baseUpdatedAt`/`clientUpdatedAt`: `updated_at` moved → conflict = per-field LWW by recency + `conflict:true`; client keeps the loser as a linked "(conflicted copy)" note. No fields = plain overwrite.
- Attachments are notes with `type != 'text'`; payload in `attachment_path`. Read the `POST /:id/attachments` branching in `notes.js`. Upload ext comes from a MIME allowlist (`IMAGE_EXT`/`AUDIO_EXT`, no SVG), not the client filename; `/uploads` is served with `nosniff` + sandbox CSP. `PUT`/`DELETE /:id/attachment` (singular — distinct from the plural create route) set or clear *that note's own* type/attachment_path in place, no new note/link; same field validation, online-only (no offline outbox — there's nothing to show until the upload actually lands). Undoable (history action `'attach'`, `before`/`after` = `{type, attachment_path, attachment_size}`) — unlike a hard `DELETE /:id`, which still deletes the file immediately and stays unreversible, these two routes deliberately leave the replaced/removed file on disk (unswept, same as the never-pruned `history` table) so undo/redo always has a real file to point back to. `POST /api/notes/attachments` (no `:id` — distinct from both routes above) creates a standalone attachment note with no link at all, for a "create" flow with no current note to hang off of; `POST /:id/attachments` and it share validation via `createAttachmentNote(req, res, parent)`, `parent` null for the standalone case. Client: `#picker-overlay` (`openPicker()`) only ever **creates** — a new note of any style (text/photo/audio/file/contact/app), linked to whatever note it was opened from or standalone — and mode `{mode:'attach'}` repurposes it to replace/clear *the currently open note's own* attachment instead (hides the title field and the "text" style choice, shows a "Remove attachment" row when the note already has one, pre-fills contact/app fields from the current value) via `api.setNoteAttachment`/`removeNoteAttachment`. Linking to an *existing* note is a separate, minimal `#link-overlay` (`openLinkModal()`, search only) — the two used to be one combined modal; kept apart because "make something new" and "point at something that already exists" are different enough actions to want their own screens, and it let the create modal always show every style (including from the header's **+ New note**, previously text-only until a connect target had been picked first). Both the note editor's ➕ (`add-link-btn`) and an empty grid cell's `+` open a small `openActionMenu` — the editor's has three items (Create a note / Add-remove attachment / Connect to note), the empty cell two (no "current note" to attach to).
- `POST /api/push/subscribe` rejects non-https endpoints and hosts resolving to loopback/link-local/RFC1918 IPs (SSRF guard in `webpush.js`, re-checked at send time). Push writes scoped by `user_id`.
- nginx (`test.ia-ai.se` → `:8040`) `client_max_body_size` caps upload size — check it before blaming the app.

## Layout

- `server/routes/`: `notes` `links` `tabs` (graph + UI state) · `session` (session/user lookup + widget token; legacy `POST` login now 410) · `auth` (passwordless magic link: `POST /api/auth/request-link` → `GET /api/auth/callback`; `login_tokens` table; `server/mailer.js` = nodemailer→Gmail SMTP, creds in gitignored `data/mail.json`, logs link if unconfigured) · `nav` (logs each move) · `stats` (note-heat / insights, all derived from `nav_events`) · `alarms` (wake-ups; dumb store — client computes fire times in the viewer's TZ since the box runs UTC. Now keyed by the `reminders` table (`GET /` list, `POST /` create with `noteId`, `PUT`/`DELETE /:id`, `POST /:id/ack|snooze|schedule`), one row per reminder so a note can carry several; `snooze` pushes `snooze_until` weeks/months out and overrides `next_at`. The legacy `notes.alarm_*` columns are dead — one-time backfilled into `reminders` under `user_version < 2` in `db.js` — remove after a release) · `agenda` (`GET /api/agenda?tz=` → `server/agenda.js` `buildAgenda`: reminders bucketed overdue/today/week/later by wall-day in an IANA zone — `?tz=` → most common `reminders.tz` → UTC — from the client-written `COALESCE(snooze_until, next_at)` instants only, plus an `openTasks` list scanned from note `content` for `- [ ]`, and an `orphans` list — notes with no links at all, so they'd otherwise never turn up while navigating the grid, most-recently-updated first, capped at 20; same "no links" signal the insights overlay's orphans list uses. Surfaced in the in-app 🔔 overlay (an "Orphaned notes" section, `openAgenda()` in `app.js`) and the widget's `?mode=agenda` (deep-linked like every other section there) — both just pass `buildAgenda`'s `orphans` through) · `digest` (opt-in scheduled push/email of the agenda; carries the same `orphans` (capped to 5 in the text/email body, a count-only line in push, full 20 on the standalone page below — doesn't count toward `isEmpty`, so it never *triggers* a digest, only rides along on one that's already going out); `GET /` = the same bundle for in-app review, `GET`/`PUT /prefs` = `users.digest_*` cols (`cadence` off/daily/weekly, `hour` local, `tz`, `channel` push/email/both, `last_sent_at`), `POST /test` sends one now; builder + text/html/push renderers in `server/digest.js` wrap `buildDigest`→`buildAgenda`. The push body lists the actual due items, not just counts; push + email carry a "see everything" link to the standalone page) · `digest-page` (mounted at **`/digest?token=…&cadence=&tz=`**, above the cookie gate, `widget_token`-authed like the widget feed — a self-contained styled HTML page with every reminder + the same (uncapped-here, so up to 20) `orphans` list + Open-in-app / Insights links; `buildDigestPage` + `digestPageDoc` in `server/digest.js`; the notification and the email "see everything" link both point here) · `push` (Web Push subscribe, endpoint SSRF-validated; VAPID keys in `data/vapid.json`; send logic in `webpush.js`) · `widget` (read-only feed, token-authed; `?mode=agenda&tz=` returns `buildAgenda` output with deep-link URLs) · `history` (undo/redo log; `history.js` records entries from other routes, `routes/history.js` reverses them) · `onboarding` (`POST /begin`, guarded by the one-time `users.onboarding_cleared_at` stamp, wipes every note the account has — links/reminders cascade away with their notes — reached by a real 🔗 app-link attachment note whose `attachment_path` is `/?ob=begin`, a same-origin URL so it's a same-tab nav landing back in `handleDeepLink`'s `ob=begin` branch, not a markdown link buried in text). New accounts are seeded (`auth.js`'s callback, brand-new-user branch → `server/onboarding.js` `seedSampleGraph()`, redirects to `/?fresh=1`) with a plain, fully static, pre-linked note graph — no dynamic behavior, nothing watches for or reacts to actions. Welcome → Skip-the-intro (the clear-demo app-link attachment itself, `type:'app'`, a tappable "🚀 Launch" card) and → a straight chain (`CHAIN` in `onboarding.js`, each note linking only to the next): Take the tour → Tap zones → Move it → the three status states → Set an alarm → Pin it → Check the agenda → Check the map → a Tips card → the closing `🎉 Clear the demo` attachment. Every note's own content is written once and ends with "When done, tap `[[Next title]]` to continue →" — the user reads, does the thing (unverified), and advances themselves.

`public/app.js`'s note-editor opens with a persistent `previewActive` flag (default preview) — an action button (pin/status/delete) rerenders via `onRerender` with no mode argument, which reuses whatever `previewActive` already is rather than resetting to edit; only an explicit open (top/bottom tap-zone, or the user's own Preview/Edit toggle) changes it.
- `server/alarm-scheduler.js`: 30s `setInterval` from `index.js`; for each `reminders` row whose due instant (`COALESCE(snooze_until, next_at)`) has passed and hasn't been pushed, sends one Web Push and stamps `pushed_at`. The client rolls `next_at` forward (and clears `pushed_at`) on every poll while open — so a recurring reminder only stays armed for closed-app delivery if the app is opened between rings.
- `server/digest-scheduler.js`: 5-min `setInterval` from `index.js`; for each user with `digest_cadence` daily/weekly whose local hour (in `digest_tz`) matches `digest_hour` and whose cadence window has elapsed since `digest_last_sent_at`, builds the digest — skips if empty (no stamp, so a later tick that hour can still send) — then null-safe compare-and-sets `digest_last_sent_at` (one delivery wins the race) and sends via `digest_channel`. Push = deep link to `/`; email via `server/mailer.js`.
- `public/app.js`: `render()` draws the grid; `goTo()`/`jumpTo()` navigate + `logNav()`; centered note is **read-only**, click opens the fullscreen editor (`buildNoteEditor`) — top half of the *center* card opens it in rendered/preview mode (clickable `[[wikilinks]]`, no keyboard), bottom half opens straight into the editable textarea (`openNoteFullscreen(mode)`/`renderNoteFullscreen(mode)`, mode `'preview'`/`'edit'`); a neighbor card's top half just centers it (same as before — the center cell is already a read-only preview), bottom half centers it **and** opens straight into editing. `attachCardDrag`→`rehomeCard` drags a card's link from center to another card (Android via Pointer Events); the editor footer's status button (`done-btn`) opens a 4-item `openActionMenu` (Normal/Waiting/To-do/Done, current one marked `active`) instead of cycling on each click — picking the already-current one is a no-op; `openActionMenu(anchor, items)` (items: `{label, onClick, active?}`) is the shared small anchored dropdown used here, by the ➕ buttons below, and anywhere else a button needs more than one action; `🎨` colour toggle, `📊` insights, `🔔` agenda (client-side "what's due" over every reminder — overdue/today/this week/later buckets from the `alarms` array in the viewer's TZ; badge = triggered count; rows Open/Snooze/✓; `buildSnoozeSelect` shared with the ring popup; an "Open tasks" section is fetched from `GET /api/agenda` since the client note cache has no `content`). `👤` account overlay also holds the **digest** settings (cadence / hour / channel selects + "Send one now"), which `PUT /api/digest/prefs` on change and call `enableAlarmDelivery()` when a push channel is turned on. `init()` → `handleDeepLink()` consumes `/?d=agenda` / `/?d=insights` (used by the digest page's buttons) to open that overlay then strip the param. `api.*` = the single server-I/O choke point: reads write-through + fall back to IndexedDB; mutators (notes/links/reminders/nav) run online→server / HTTP-error→throw / offline-or-drop→optimistic+`enqueue`. Write-queue block (`outbox`/`flushOutbox`/`sendEntry`/`remapId`/`enqueue` coalescing/`handleConflict`/`openSyncPanel`) sits after `syncLinks`.
- Markdown: `content` is GFM markdown, rendered via vendored `public/vendor/marked.min.js` + `purify.min.js` (`renderMarkdownInto`); `[[Title]]`/`[[#id]]` wikilinks resolve against `allNotesCache` (a marked inline extension) and navigate on click; task checkboxes toggle and write back through `toggleTaskInSource` + `PUT /api/notes/:id`. Editor has a Preview toggle; the textarea has `[[` autocomplete (`attachWikiAutocomplete`) that also creates the graph link.
- Search: `GET /api/notes/search?q=` over FTS5 (`notes_fts` external-content table + triggers in `db.js`, one-time `'rebuild'` gated by `PRAGMA user_version`). Topbar does an instant local title filter then swaps in debounced server results.
- `public/style.css`: phone type scale lives only in the shared `@media (max-width:640px), (max-height:500px)` block — keep `font-size` out of the per-orientation blocks.
- `public/sw.js`: PWA install + **shell precache** (stale-while-revalidate; `CACHE_VERSION`; never intercepts `/api` `/uploads` `/share` `/digest` — app.js owns those) + push delivery. New worker → posts `sw-activated` → app's "reload for new version" toast. Settings → Account → **Check for updates** (`runUpdateCheck`/`checkForUpdate` in `app.js`) does `reg.update()` then re-fetches each cached js/css/html/manifest file with `?__update=<ts>` (which `sw.js` passes straight to the network, uncached — a plain fetch would be answered from the stale cache) and swaps in any whose bytes differ, so a `public/` change lands without waiting for the 2nd load. Alarm pushes carry `reminderId` + "Snooze 10m/1h" buttons; worker POSTs `/api/alarms/:id/snooze` itself (fixed `now + N`) and re-shows on failure. `type:'digest'` push shows the item list, opens its `url` (`/digest?token=…`).
- `public/vendor/`: `marked` `purify` `leaflet.min.{js,css}`+`images/` vendored (Leaflet was CDN) — map UI works offline, tiles don't.
