# CLAUDE.md

Personal notes app: notes are a link graph, rendered as a 3x3 grid around one centered note. Express + better-sqlite3 (`server/`), no-build vanilla-JS IIFE (`public/`). No bundler, no tests, no lint.

This checkout (`/srv/notes`, port **8050**) serves **notes.ia-ai.se**. It was forked from `/srv/nico-server` (port 8040, **test.ia-ai.se**) on 2026-09-15 — same codebase, independent data from that point on (no sync between the two). **`test.ia-ai.se` was retired 2026-10-05**: the old app no longer runs; `/srv/nico-server/redirect.js` (bare node on :8040, user-crontab `@reboot`) 301s every request to the same path on notes.ia-ai.se. Its `data/notes.db` is kept untouched (holds 7 post-fork notes never copied here). Proper fix = nginx `return 301` in `/etc/nginx/sites-available/test` (needs root), then drop the redirect process + crontab line.

`notes-android/` is a sub-project in this same git repo: `se.iaai.notes`, native home-screen widgets (a live 3x3 grid, an agenda summary, a nudge tile) plus `SetAlarmActivity` (the web app's "Add phone alarm") for whichever `base_url` (currently notes.ia-ai.se) is baked into it. No app UI of its own, deliberately — the app itself is installed via "Add to Home Screen" on the PWA, not this APK; see `notes-android/CLAUDE.md` for why. Its own Gradle build, unrelated to `npm`/`server/`.

## Run

- `npm start` (= `node server/index.js`). `npm install` for deps.
- Env: read from gitignored `.env` at the repo root (`process.loadEnvFile` at the top of `index.js`; real env vars win) — here `PORT=8050`, `PUBLIC_ORIGIN=https://notes.ia-ai.se`. Vars: `PORT` (**8050** here), `HOST` (127.0.0.1), `MAIL_INGEST` (`1` = poll the mail-in address — on here only, so `test.ia-ai.se` sharing the same Gmail can't double-import), `DB_PATH` (sqlite file, for testing on a copy), `SEED_USER_EMAIL`, `PUBLIC_ORIGIN` (link base for widget/digest/auth/account links; request routes fall back to forwarded headers, the schedulers to `http://127.0.0.1:PORT` — so set it or digest push/email links are unusable), `VAPID_CONTACT`.
- **Restart after any `server/` change** — code and `db.js` migrations only load on boot. `public/` static, no restart — but `sw.js` precaches the shell (stale-while-revalidate), so a `public/` change lands on the **2nd** load; bump `CACHE_VERSION` to purge.
- A PostToolUse hook in `.claude/settings.local.json` (gitignored, per-machine) runs `systemctl restart notes.service` after any `server/**` edit. It works for `devuser` (non-root Claude runs as it) via the polkit rule `/etc/polkit-1/rules.d/50-notes-restart.rules` (installed 2026-10-05), which lets `devuser` start/stop/restart `notes.service` only.
- Runs as systemd `notes.service` (enabled at boot, `Restart=always`, logs append to `data/server.log`); this is also what does the mail-in poll. Restart with `systemctl restart notes` — never start a bare 2nd instance (WAL lock clash). `/srv/mailrouter` (old mail router) is stopped + disabled.

## Gotchas

- `data/notes.db` is the **only copy of real user data**. Never rm/reset it. To test server logic, `Database(src).backup(dest)` and run with `DB_PATH` on another `PORT`.
- Multi-user: opaque `nico_sess` cookie → `sessions` row → `req.userId`/`req.sessionId` (see `server/sessions.js`); every route scopes by `req.userId`. Session created on email login (`POST /api/session`), destroyed on `DELETE /api/session`. The legacy raw-id `nico_uid` cookie is auto-upgraded to a session by the `/api` middleware in `index.js` (migration shim — remove after users have migrated). `COOKIE_INSECURE=1` drops the `Secure` flag for local HTTP testing. `data/` + `node_modules/` gitignored.
- Exception to the cookie gate: `/api/widget?token=` and `/digest?token=` are token-authed, mounted **above** it in `index.js`. Token in `users.widget_token`, minted lazily by `server/widget-token.js` `ensureWidgetToken()` (used by `GET /api/session` and the digest link builders), rotate/revoke via `POST`/`DELETE /api/session/widget-token`. So is **`/calendar.ics?token=`** (`routes/calendar.js` → `server/calendar-feed.js`): an iCalendar subscription of every `kind='time'` reminder on a not-done note (repeat days → weekly `RRULE`, one-time date → single event, `TZID` = the reminder's `tz`, 0-min `VALARM`; nudges/location left out, snooze ignored). It has its **own** token, `users.calendar_token` (`ensureCalendarToken`, rotate `POST /api/session/calendar-token`) — not `widget_token`, since this URL is stored on Google's/Apple's servers and `widget_token` can also write (`/api/widget/location`). Each fetch stamps `users.calendar_fetched_at`; `GET /api/session` returns `calendarToken`/`calendarFetchedAt`, and the client treats "fetched in the last 3 days" (`calendarFeedLive()`) as subscribed. UI: Settings → Integrate → Calendar subscription (URL, Add to Google Calendar via `?cid=webcal://…`, Copy, Reset).
- **Reminder → phone** (note editor ⏰, `onAlarmButton` in `app.js`): with a timed reminder it opens a menu — Edit reminder, **📅 Add to calendar** (Google Calendar `action=TEMPLATE` link incl. `recur`; only while the feed isn't live) and, on Android, **⏰ Add phone alarm** (only repeating or within 24 h — a clock alarm has no date): an `intent://alarm?…#Intent;scheme=iaainotes;package=se.iaai.notes;…` URL into the companion APK's `SetAlarmActivity` (Chrome won't launch the clock's own `SET_ALARM`), falling back to `/?d=integrate` (the APK download) when it isn't installed. Both one-way copies.
- **Reminder outcomes** (`reminder_events`, `server/reminders.js`): every Done / Skip (`POST /api/alarms/:id/ack` with `outcome` `done`|`skip`, default `done`) and Snooze is logged with `day` = local date in the reminder's `tz`. A track-2 nudge's Done then offers the 1-5 toast (`askNudgeRating` → `POST /:id/rate {at, rating}`, matched by the ack's own `at`, so it also works through the outbox as `reminder.rate`). Nudges opt in per reminder (`reminders.track`: 0 = info only, the default — a plain toast, nothing logged; 1 = Done/Skip/Snooze; 2 = also the ★ rating, a toast of five centred single-star buttons) via two on/off toggle buttons (✅ Track, ⭐ Rate — Rate on turns Track on, Track off turns Rate off) in the alarm editor's Nudge section. Done/Skip/Snooze appear on a tracked nudge's toast, the ring popup (Snooze/Skip/Done/✕) and agenda rows (⏭/✓, hidden on an info-only nudge) — all through `finishReminder` in `app.js`. `weekStats` (last 7 days, counted from the first logged answer: `{done, scheduled, avgRating}`) feeds `?mode=nudge`'s `week`, which the Android nudge tile shows as `✓ 5/7 · ★ 3.8`. Stats come from `daySeries` (per local day: `done`/`skip`/`missed`/`open`/null-not-scheduled, counted from the first logged answer) + `summarize`; `GET /api/alarms/:id/stats?range=month|year|all` feeds the **📈 Statistics** view (`openNudgeStats` in `app.js`, button in the nudge editor for a saved tracked nudge, and Insights' "Practice — last 30 days" section): stat tiles, a Mon–Sun calendar (month) or done-% bars per week/month (year/all), a separate ★ rating line, a table view; hand-rolled SVG on theme tokens, online-only. The digest's **Practice (last 7 days)** section (`buildPractice` in `server/digest.js`; text, email, `/digest` page — not push, not `isEmpty`) shows each tracked nudge as `●●○◐●●◌  done 5 of 7 days · skipped 1 · missed 1 · ★ 3.8 · 🔥 3`. Reminder 28 ("Health") holds a year of **invented** demo history (2025-10-01 → 2026-10-06, rows whose `at` ends in `:00.000Z`).
- **Share to app** (editor ➕ → 📲, `shareNoteToApp`): Web Share API with the decrypted text (`[[wikilinks]]` flattened to titles), the attachment file itself (offline `assets` copy first; a slow fetch gets a toast with a Share button because `navigator.share` needs fresh user activation), a contact as text, an app note as its URL; clipboard fallback.
- Schema changes: idempotent `PRAGMA table_info` + `ALTER TABLE` in `db.js`, not `CREATE TABLE` edits.
- **Backups and new schema.** A new *column* needs nothing: backups copy whole rows and restore takes the columns both sides have. A new *table* that points at notes or holds per-user graph data must be added to `server/snapshots.js` (`TABLES`, `clearCurrent`, `loadRows`, `writeAccountDb`'s `sources`) — otherwise backups silently leave it out (and a restore can hit its foreign keys). Same for a new per-user setting column on `users` (`USER_COLS`).
- `GET /api/notes/:id/neighbors` returns `{ parent, neighbors }` (not an array). `neighbors` ranked by `nav_events` history (`SCORE_W`/`HALF_LIFE_DAYS` in `notes.js`); cold-start = link recency. `parent` = probable back-link. `GET /api/links` = whole link graph, mirrored to IndexedDB for offline neighbour recompute (link-recency = cold-start).
- **Offline (PWA).** `public/store.js` = IndexedDB wrapper (stores `notes`/`links`/`outbox`/`blobs`/`meta`/`neighbors`/`assets`, DB **v3**). Reads write-through; fall back to the mirror on fetch failure; SW-cached shell boots offline. Offline (or mid-request-drop) writes = optimistic + `outbox`, replayed in order by `flushOutbox()` on reconnect / 30 s tick / `visibilitychange`. Offline-created rows get a `tmp:`/`rtmp:` id → real on create-sync (`remapId`/`remapReminderId`). Reminders mirror whole in `meta['alarms']`. 4xx → topbar pill → sync panel (Retry/Discard); network/5xx → retry.
- **Bars reach into referenced spaces.** The to-do and alarm header bars are "everything under the current note": `subtreeTodos`/`subtreeIdsFor` in `server/notes.js` go through `crossScopeSubtree`, which, for a *personal* center, also follows this user's `personal_refs` from any note in that subtree into the referenced shared note's subtree in its own space (member check included). One-way: a space center never pulls in personal notes. Space to-dos carry `shareId`/`shareTitle`, and reminders now carry `noteStatus` (+ `shareId`/`shareTitle`), because `allNotesCache` only holds the current scope; chips show `🔗Space`. Pins are still a shared `notes.pinned` column per scope, so they're deliberately left out. Every `buildAgenda` row on a space note (reminders, nudges, `todos`, `openTasks`, `orphans`) carries `shareId`/`shareTitle`, and the 🔔 overlay (`openAgenda`) plus every digest renderer (`bySpace` in `server/digest.js`: text, email, the `/digest` page) group the whole agenda by space: 👤 Personal first, then spaces by name, the usual sections inside each, headed only when a space has items. The 4-line push stays flat, with a ` 🔗Space` suffix. An encrypted account's 🔔 keeps the server's space rows and replaces only the personal half with its local recompute.
- **Grid coherence offline.** `getNeighbors` caches the server-ranked `{ parent, neighbors, links }` per note (`.p`/`.score` kept) in the `neighbors` store; offline serves that blob (deleted-filtered vs `allNotesCache`; `cache.patchNeighborLink` fixes it on offline link/unlink) → cell order = last online visit; never-visited → link-recency. `note-heat`/`insights` cached in `meta` (`cachedStat`) → the 🔥 tint keeps working offline. 🔥 (header colour-coding toggle) is just off / note heat (tint = `--note-heat`); the old "path heat" mode was dropped — it duplicated the neighbour order.
- **Warm cache (phase 5).** The list endpoint (`GET /api/notes`) omits `content`/`attachment_path` to stay light, so historically only an individually-opened note had them mirrored — offline, a never-opened note showed literal `"undefined"` in the editor (and risked autosaving that over the real text once back online). `warmCache()` (called from `init()` and `reconnect()`, never awaited by rendering) now pulls `GET /api/notes/full` (`{id, content, attachment_path, updated_at}` for every note — text is cheap even at thousands of notes, so no budget) and merges it via `cache.mergeFullNotes` (same "skip a `_dirty` note" rule as `mergeNotes`). Where content is still genuinely uncached (a note created elsewhere since this device's last successful warm cache), `buildNoteEditor`/`makeCenterCell` show "Not available offline" and disable that note's title/text editing (`currentNote.content == null` is the tell — the server never returns `undefined`, only `''`) rather than risk clobbering it. Attachment *files* are a separate, budgeted download: `warmAttachmentCache()` walks `GET /api/notes/attachments-manifest` (image/audio/file notes only, newest-`updated_at`-first, with `notes.attachment_size` — backfilled lazily by that route via `fs.statSync` for rows uploaded before the column existed) and downloads into the `assets` store up to `assetCacheBudget()`: an environment baseline (Android+installed 500MB / Android browser tab 150MB / iOS installed 200MB / iOS browser tab 50MB / desktop 500MB — installed PWAs get Chrome's automatic persistent-storage grant and a real quota that large, a bare tab can vanish on uninstall/clear, iOS Safari purges unused tab storage after 7 days) clamped to half of `navigator.storage.estimate()`'s headroom. `meta['assetIndex']` tracks `{size, updatedAt}` per cached path so budget/eviction math never loads blobs into memory; anything no longer in the manifest or pushed past the budget line by newer attachments is evicted. `resolveMediaUrl` serves straight from the network when online (unchanged) and only consults `assets` offline; a miss renders `mediaUnavailableNotice()` ("📵/🖼/🔊 Not available offline") instead of a broken image/audio player or dead download link.
- **Themes** (🎨 header button → `#theme-overlay`, tabs App / This note). `public/themes.js` is the single model, a UMD file loaded by the browser (`window.NicoThemes`, in `<head>` so `boot()` pre-paints the cached colours) **and** `require`d by the server (`../public/themes.js`) — `sanitizeStyle` whitelists every value (hex colours, font key, `preset:<key>`|`/uploads/<file>`|`none` images, hue 0-359, dim 0-90, glow 0-100, `cardAlpha` 0-100 = card background opacity, shown in the editor as "Transparency" = 100 − alpha, applied via `--card-alpha` in `.cell`'s `color-mix` + the card image layers, `textFx` `auto|off|shadow|outline` → `--text-shadow` on `.cell`: a halo in the opposite tone to the text colour, `auto` only over a card image with dim < 50 or a translucent card over a page image — see `textShadow()`) since it ends up in inline CSS — **the server `require`s this file, so a `themes.js` change needs a server restart** (the hook only fires on `server/**` edits, and an old process silently drops fields it doesn't know); Colours cover the whole UI, not just the reading surface — `COLOR_GROUPS` = Core (`bg`/`surface`/`text`/`accent`/`border`) + Tabs & status (`pin`/`todo`/`waiting`/`latest`/`noteHeat`/`alarm`/`danger`, i.e. the pin/todo/waiting/latest/alarm header bars, the note-heat colour-coding tint, and delete/danger buttons), `COLOR_KEYS` is both flattened; every key in `AUTO_CONTRAST_KEYS` (`accent` + all seven tab/status ones) gets its own auto-computed `--<name>-contrast` (light or dark text, whichever reads) the same way `accent-contrast` always worked — `effectiveColors`/`cssVars` compute all of it, the theme editor's colour rows are just `COLOR_GROUPS` rendered generically, so a new colour key needs no editor-UI change. 11 built-in presets (`PRESETS`): Light/Dark/Neon plus 8 more (Sunset/Ocean/Aurora/Forest/Rose Quartz/Slate/Sepia/Midnight — 4 pair a colour palette with a built-in background image, 4 are flat colour). `cssVars` maps a style to CSS custom properties (`--bg/--surface/--text/--accent/--border/--muted` + the seven tab/status colours and their `-contrast` pairs, `--font-body`, `--bg-*`/`--card-*` `img|hue|dim`, `--shadow` glow). A *style* is sparse — absent = inherit — and `mergeStyles` merges field by field. Fonts are vendored woff2 in `public/vendor/fonts/` (`@font-face` in `style.css`, precached by `sw.js`, OFL — see `LICENSES.txt`); preset images are pure CSS gradients so the hue slider is just `filter: hue-rotate` on a `::before` layer (`.theme-bg` for the page, `.cell.has-card-img` for cards). Two stores: account **app theme** = `users.theme_prefs` JSON `{active, custom[]}` (`GET`/`PUT /api/theme`; client keeps it in localStorage `nico-theme-prefs-<uid>` with a `dirty` flag, `syncThemePrefs()` on boot/reconnect/edit, local dirty wins) and per-note `notes.theme` JSON + `theme_children` (`PUT /api/notes/:id/theme` → `api.setNoteTheme`, outbox kind `note.theme`, deliberately does **not** bump `updated_at` and is not in undo history; the list route carries both columns). Effective style = app theme ← ancestors with `theme_children` (root first) ← the note's own (`styleFor` in `app.js`); "ancestors" = the **server's** inferred hierarchy via `GET /api/notes/hierarchy-parents` (fetched per `render()` — personal graph only, since a space has no `theme_children` of its own to cascade through — mirrored in `meta['hierarchyParents']` for offline — the local rebuild can't see `created_from_note_id`); also doubles, via `linkRelationOf`, as the guessed-direction source for a neighbor card's relation icon — always one of the three real relations (⤵ child/⤴ parent/🔀 cross), dimmed (`.is-guessed`) when guessed rather than explicit; an unresolved link (nothing explicit, and even the hierarchy has no direction to offer) reads as a guessed 🔀 cross-reference, never a separate "unmarked" gear icon. While viewing a shared space, `refreshThemeContext` fetches the space's own scoped map instead (`GET /api/shares/:id/hierarchy-parents` → `server/shares.js`'s `hierarchyParents`, both wrapping `hierarchy.js`'s scope-generic `hierarchyParentsMap`) — online-only, no offline mirror (same as `getShareNotes`/`getShareLinks`) — so the relation-icon guess still works there even though theme cascading itself doesn't. Two scopes (`applyScreenTheme`): the **app theme** styles the chrome (header, bars, dialogs) as vars on `<html>`; the centered note's resolved style is applied only as inline vars on `#grid`, `#note-overlay` (the editor) and `.theme-bg` (page background), so a note theme never touches the header or its font. Every cell gets its own note's vars inline only when they differ from the grid's (`applyCellTheme`); live edits re-style in place via `restyleAll()` (no full render). Uploads: `POST /api/theme/image` (client downsizes to 1600px JPEG first; MIME allowlist, 8 MB, recorded in `theme_images`; a theme may only reference the user's own; `sweepImages` deletes unreferenced ones after a 1 h grace on each theme save). Offline, uploaded images come from the `assets` store as object URLs (`warmThemeImages()`, `prepareOfflineThemeImages()`) — not in `assetIndex`, so attachment eviction never touches them. Editing a built-in theme forks it into a custom one.
- `PUT /api/notes/:id` + optional `baseUpdatedAt`/`clientUpdatedAt`: `updated_at` moved → conflict = per-field LWW by recency + `conflict:true`; client keeps the loser as a linked "(conflicted copy)" note. No fields = plain overwrite.
- Attachments are notes with `type != 'text'`; payload in `attachment_path`. Read the `POST /:id/attachments` branching in `notes.js`. Upload ext comes from a MIME allowlist (`IMAGE_EXT`/`AUDIO_EXT`, no SVG), not the client filename; `/uploads` is served with `nosniff` + sandbox CSP. A `type:'file'` upload whose stored file is an image/audio becomes an image/audio note (`server/attachment-kind.js` `uploadedFileType`; same module holds mail-in's `classify`; existing rows converted once under `user_version < 3` in `db.js`). `PUT`/`DELETE /:id/attachment` (singular — distinct from the plural create route) set or clear *that note's own* type/attachment_path in place, no new note/link; same field validation, online-only (no offline outbox — there's nothing to show until the upload actually lands). Undoable (history action `'attach'`, `before`/`after` = `{type, attachment_path, attachment_size}`) — unlike a hard `DELETE /:id`, which still deletes the file immediately and stays unreversible, these two routes deliberately leave the replaced/removed file on disk (unswept, same as the never-pruned `history` table) so undo/redo always has a real file to point back to. `POST /api/notes/attachments` (no `:id` — distinct from both routes above) creates a standalone attachment note with no link at all, for a "create" flow with no current note to hang off of; `POST /:id/attachments` and it share validation via `createAttachmentNote(req, res, parent)`, `parent` null for the standalone case. Client: `#picker-overlay` (`openPicker()`) only ever **creates** — a new note of any style (text/photo/audio/file/contact/app), linked to whatever note it was opened from or standalone — and mode `{mode:'attach'}` repurposes it to replace/clear *the currently open note's own* attachment instead (hides the title field and the "text" style choice, shows a "Remove attachment" row when the note already has one, pre-fills contact/app fields from the current value) via `api.setNoteAttachment`/`removeNoteAttachment`. Linking to an *existing* note is a separate, minimal `#link-overlay` (`openLinkModal()`, search only) — the two used to be one combined modal; kept apart because "make something new" and "point at something that already exists" are different enough actions to want their own screens, and it let the create modal always show every style (including from the header's **+ New note**, previously text-only until a connect target had been picked first). Both the note editor's ➕ (`add-link-btn`) and an empty grid cell's `+` open a small `openActionMenu` — the editor's has three items (Create a note / Add-remove attachment / Connect to note), the empty cell two (no "current note" to attach to).
- **Done-cascade.** Changing a note's status from the editor's status menu first runs `openStatusCascadeDialog` (`app.js`). → done: lists every still-open note under it in `hierarchyParents` (explicit `created_from_note_id` chains pre-ticked, guessed ones unticked with a "Not a child" button = `setLinkRelation(...,'cross')`). done → reopened: lists the notes closed *with* it. Ticked ids go as `cascade` on `PUT /api/notes/:id/status` → `setStatus` in `server/notes.js`, which stamps `notes.done_with_note_id` + `done_prev_status` on cascaded notes (reopen restores each note's own earlier status; any direct status change clears both columns) and records one `status` history entry with a `cascade` array that undo/redo replay (`applyStatusCascade` in `routes/history.js`). The hierarchy inference (`buildHierarchy`, `/neighbors`, and their client copies) no longer skips 'done' parents (that made children re-parent the moment a note was completed) and now ignores `links.kind='cross'` links as guessed parents.
- **Share this note** (➕ → 🔗, `openShareFlow` → `openShareDialog` in `app.js`): new space or an existing one, then a checklist of `GET /api/shares/candidates` (now each with `parentId`, shown as an indented tree, all ticked; the note itself fixed; a new space's name field is in the same dialog). `createShare`/`addNoteToShare` record one `share` history entry `{shareId, noteIds, created, droppedLinks}` and return its `historyId` (the toast's Undo button). Undo (`undoShare` in `routes/history.js`) moves the notes back out together via `moveNotesOutOfShare` (also the body of `removeNoteFromShare`), restores the straddling links with their original `created_at`/`kind`, and dissolves a space it created if left empty; redo re-joins/moves in again. Undo/redo routes save `p` back to `history.payload` (redo refreshes `droppedLinks`).
- **Content encryption** (opt-in, zero-knowledge — `public/crypto.js`, `server/encryption.js`, `docs/plan/08-offline-privacy.md`). The recovery key is never stored; each device keeps the derived AES key in IndexedDB `meta['encKeyRaw-<uid>']` (kept on sign-out, deliberately). Invariant: an encrypted account's **personal** notes are `ncv1:` ciphertext, its notes **in a shared space** are plaintext (no other member has the key). The server can't encrypt, so anything it writes (mail-in, importer, restore of plaintext rows, notes moved out of a space by undo/another member) is caught by `sweepContentEncryption()` (app open, reconnect, unlock, after an import): `GET /api/encryption/pending` → `{encrypt, decrypt}`, client converts, `POST /api/encryption/sweep {items:[{id, content, expect}]}` — compare-and-set on `expect`, direction-checked (`convertOne`), no `updated_at`/history change. Moving notes **into** a space sends their decrypted text along (`plaintextForShare` → `plaintext` on `POST /api/shares` / `POST /api/shares/:id/notes`, written in the move's transaction by `decryptMoved`); a locked device can't share encrypted notes.
- **Undo coverage** (`routes/history.js`). Beyond notes/status/pin/attach/share: `link`/`unlink`/`rehome` payloads carry the link's `created_at`/`kind` (+ `stamped` = the parent guess `links.js` create made) so undo/redo restore them exactly; `ref`/`unref` (`addRef`/`removeRef`); `unshare` (Remove from space — `captureUnshare` saves in-space links + refs into the note, undo moves it back via `moveNotesIntoShare` and restores them); `reminder` (`server/reminders.js`'s exported create/update/remove are recording wrappers: whole raw row `before`/`after`, `setReminderState` writes it back with the same id; remove also saves the settings in `notes.last_reminder`, which the alarm editor prefills from when the note has no reminder); `restore` (backup restore: `server/snapshots.js` takes a `VACUUM INTO` copy first — `snapshots/` next to the DB, 10 kept per user — and undo/redo swap the account's rows from a snapshot outside a transaction, appending a fresh history row since the history table is swapped too; the restore no longer deletes the replaced graph's upload files). **Server backups** (Settings → Account → Server backups): `GET`/`POST /api/account/snapshots`, `GET /:id/check`, `POST /:id/restore` (snapshots first → same undoable `restore` entry), `DELETE /:id`; ids are the snapshot file names (`<uid>-<ms>-manual|pre-restore|post-restore.db`, `ownsSnapshot` checks owner + exact basename); manual and automatic snapshots are pruned separately (10 each). **Downloads** (Settings → Import & export) are three files, two of which pair up: **backup** = `GET /api/account/backup` → `notes-backup-<date>.zip` holding only `account.db` (`writeAccountDb`: this account's rows, same table definitions, `backup_meta` with source `user_id`; content stays ciphertext for an encrypted account); **export** = `notes-export-<date>.zip`, built **in the browser** (`exportBtn` handler in `app.js`, vendored `public/vendor/fflate.min.js`) because only the client can decrypt — one Markdown file per personal note, files linked as `../attachments/<name>`; **attachments** = `POST /api/account/attachments` (hidden-iframe form post) → `notes-attachments-<date>.zip` of `attachments/<name>`, shared by both (the client adds `names` for inline embeds it found in decrypted text, since the server can't see those). Extracting export + attachments into one folder gives a working vault; the Markdown importer (`POST /api/import`, `files[]` up to 2) takes the pair together. Restore is two steps — `POST /api/account/import/check` (multipart `files[]`: the backup zip, plus optionally the attachments zip; staged in `snapshots/staging/`, 1 h TTL; returns `token`/`filesToken` + the analysis: `missingColumns`/`missingTables`, `leavingSpaces`, `remap` when note ids are taken → new ids, no undo history; `files.unavailable` = referenced but neither on disk nor in the attachments zip) then `POST /import/apply {token, filesToken}` (pre-restore snapshot, writes every allowlisted attachment file missing on disk under its original name — not limited to visible references, since encrypted inline embeds can't be seen — `restoreFromFile(..., {untrusted:true})` re-validates: share_id only for spaces you're in, attachment notes must point into `/uploads/`, themes/theme prefs through the theme sanitizer). Same-server restores need only the backup file. No support for older formats (data.json / single-zip) — dev mode. Restore copies the columns both sides have, so older backups still load (missing columns get defaults).
- `POST /api/push/subscribe` rejects non-https endpoints and hosts resolving to loopback/link-local/RFC1918 IPs (SSRF guard in `webpush.js`, re-checked at send time). Push writes scoped by `user_id`.
- nginx `client_max_body_size` caps upload size — check it before blaming the app. **Pending root change:** `/etc/nginx/sites-available/notes` has `client_max_body_size 50M`; backup restore uploads the whole .zip (the app accepts up to 1 GB, and a full export with attachments is already ~100 MB), so raise it to `1G` (and consider `proxy_read_timeout`/`client_body_timeout` for slow uploads), then `nginx -t && systemctl reload nginx`. Until then a restore of a backup over 50 MB fails with HTTP 413.

`public/app.js`'s note-editor opens with a persistent `previewActive` flag (default preview) — an action button (pin/status/delete) rerenders via `onRerender` with no mode argument, which reuses whatever `previewActive` already is rather than resetting to edit; only an explicit open (top/bottom tap-zone, or the user's own Preview/Edit toggle) changes it.
- `server/mail-ingest.js` (mail-in): email `alf.cromsjo+notes@gmail.com` or `+note@` (= `<data/mail.json user>+notes@…` / `+note@…`, the latter the old mailrouter address; override `ingestAddress`/`MAIL_INGEST_ADDRESS`, comma-separated) → private, unlinked note in the account whose `users.email` equals the From. **IMAP polling of that Gmail account (60 s, same app password as `mailer.js`), not a local MTA** — the address's MX is Google's, so nothing on this box could ever receive it. Dedup + state in `mail_ingest` (keyed by Gmail X-GM-MSGID; `__cursor__` row = first-enabled instant, older mail never imported). Trusted = self-sent (`\Sent` label + From is the Gmail account) or Gmail's **topmost** `Authentication-Results: mx.google.com` shows dmarc / aligned dkim / aligned spf pass; else a `pending` row + confirm mail (message quoted) to the account's own address → `routes/mail-in.js` (`/api/mail-in/confirm`, above the cookie gate; GET shows a button, POST creates — prefetch-safe; re-fetches the mail from IMAP, nothing stored meanwhile; 3-day TTL, 5 confirms/user/hour). - `server/alarm-scheduler.js`: 30s `setInterval` from `index.js`; for each `reminders` row whose due instant (`COALESCE(snooze_until, next_at)`) has passed and hasn't been pushed, sends one Web Push and stamps `pushed_at`.
