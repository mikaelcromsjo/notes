# CLAUDE.md

Personal notes app: notes are a link graph, rendered as a 3x3 grid around one centered note. Express + better-sqlite3 (`server/`), no-build vanilla-JS IIFE (`public/`). No bundler, no tests, no lint.

## Run

- `npm start` (= `node server/index.js`). `npm install` for deps.
- Env: `PORT` (8040), `HOST` (127.0.0.1), `DB_PATH` (sqlite file, for testing on a copy), `SEED_USER_EMAIL`, `PUBLIC_ORIGIN` (widget-feed link base; else forwarded headers), `VAPID_CONTACT`.
- **Restart after any `server/` change** — code and `db.js` migrations only load on boot. `public/` is static, no restart — but the service worker now precaches the shell (stale-while-revalidate), so a `public/` change is live on the **second** load; bump `CACHE_VERSION` in `sw.js` when you need old caches purged.
- A PostToolUse hook in `.claude/settings.local.json` (gitignored, per-machine) auto-restarts the bare `node server/index.js` after any `server/**` edit, logging to `data/server.log`.
- A bare `node server/index.js` is usually already running (no systemd). Check `ps aux | grep server/index.js` before a 2nd instance — WAL lock clash.

## Gotchas

- `data/notes.db` is the **only copy of real user data**. Never rm/reset it. To test server logic, `Database(src).backup(dest)` and run with `DB_PATH` on another `PORT`.
- Multi-user: opaque `nico_sess` cookie → `sessions` row → `req.userId`/`req.sessionId` (see `server/sessions.js`); every route scopes by `req.userId`. Session created on email login (`POST /api/session`), destroyed on `DELETE /api/session`. The legacy raw-id `nico_uid` cookie is auto-upgraded to a session by the `/api` middleware in `index.js` (migration shim — remove after users have migrated). `COOKIE_INSECURE=1` drops the `Secure` flag for local HTTP testing. `data/` + `node_modules/` gitignored.
- Exception to the cookie gate: `/api/widget?token=` and `/digest?token=` are token-authed, mounted **above** it in `index.js`. Token in `users.widget_token`, minted lazily by `server/widget-token.js` `ensureWidgetToken()` (used by `GET /api/session` and the digest link builders), rotate/revoke via `POST`/`DELETE /api/session/widget-token`.
- Schema changes: idempotent `PRAGMA table_info` + `ALTER TABLE` in `db.js`, not `CREATE TABLE` edits.
- `GET /api/notes/:id/neighbors` returns `{ parent, neighbors }` (not an array). `neighbors` ranked by `nav_events` history (`SCORE_W`/`HALF_LIFE_DAYS` in `notes.js`); cold-start = link recency. `parent` = probable back-link. `GET /api/links` dumps the caller's whole link graph — the client mirrors it into IndexedDB so it can recompute neighbors (link-recency order = server cold-start) with no connection.
- **Offline (PWA).** `public/store.js` = an IndexedDB wrapper (`notes`/`links`/`outbox`/`blobs`/`meta`/`neighbors`, DB **v2**). Reads write-through to that mirror and fall back to it when a fetch fails; the shell is SW-cached so the app boots offline. Writes made offline (or that drop mid-request) go optimistic + into `outbox`, replayed in order by `flushOutbox()` on reconnect / a 30 s tick / `visibilitychange`. Offline-created rows carry a `tmp:`/`rtmp:` id rewritten to the real id on create-sync (`remapId`/`remapReminderId`). Reminders mirror whole in `meta['alarms']`. A queue entry that fails with a 4xx is surfaced in the topbar pill → sync panel (Retry/Discard); network/5xx just retries.
- **Grid coherence offline.** `getNeighbors` caches each note's server-ranked `{ parent, neighbors, links }` (with `.p`/`.score`) in the `neighbors` store; offline it serves that blob (filtered against `allNotesCache` for deletes; patched by `cache.patchNeighborLink` on offline link/unlink) so cell order + path-heat match the last online visit, falling back to link-recency only for never-visited notes. Stats blobs (`note-heat`/`clusters`/`insights`) are cached in `meta` via `cachedStat` so the `note`/`cluster` colour modes keep their tints offline.
- `PUT /api/notes/:id` takes optional `baseUpdatedAt` + `clientUpdatedAt`: if the row moved since `baseUpdatedAt` it's a conflict — per-field last-write-wins by recency, `conflict:true` in the response, and the client keeps the loser as a linked "(conflicted copy)" note. No fields sent = plain overwrite (unchanged).
- Attachments are notes with `type != 'text'`; payload in `attachment_path`. Read the `POST /:id/attachments` branching in `notes.js`. Upload ext comes from a MIME allowlist (`IMAGE_EXT`/`AUDIO_EXT`, no SVG), not the client filename; `/uploads` is served with `nosniff` + sandbox CSP.
- `POST /api/push/subscribe` rejects non-https endpoints and hosts resolving to loopback/link-local/RFC1918 IPs (SSRF guard in `webpush.js`, re-checked at send time). Push writes scoped by `user_id`.
- nginx (`test.ia-ai.se` → `:8040`) `client_max_body_size` caps upload size — check it before blaming the app.

## Layout

- `server/routes/`: `notes` `links` `tabs` (graph + UI state) · `session` (session/user lookup + widget token; legacy `POST` login now 410) · `auth` (passwordless magic link: `POST /api/auth/request-link` → `GET /api/auth/callback`; `login_tokens` table; `server/mailer.js` = nodemailer→Gmail SMTP, creds in gitignored `data/mail.json`, logs link if unconfigured) · `nav` (logs each move) · `stats` (note-heat / clusters / insights, all derived from `nav_events`) · `alarms` (wake-ups; dumb store — client computes fire times in the viewer's TZ since the box runs UTC. Now keyed by the `reminders` table (`GET /` list, `POST /` create with `noteId`, `PUT`/`DELETE /:id`, `POST /:id/ack|snooze|schedule`), one row per reminder so a note can carry several; `snooze` pushes `snooze_until` weeks/months out and overrides `next_at`. The legacy `notes.alarm_*` columns are dead — one-time backfilled into `reminders` under `user_version < 2` in `db.js` — remove after a release) · `agenda` (`GET /api/agenda?tz=` → `server/agenda.js` `buildAgenda`: reminders bucketed overdue/today/week/later by wall-day in an IANA zone — `?tz=` → most common `reminders.tz` → UTC — from the client-written `COALESCE(snooze_until, next_at)` instants only, plus an `openTasks` list scanned from note `content` for `- [ ]`) · `digest` (opt-in scheduled push/email of the agenda; `GET /` = the same bundle for in-app review, `GET`/`PUT /prefs` = `users.digest_*` cols (`cadence` off/daily/weekly, `hour` local, `tz`, `channel` push/email/both, `last_sent_at`), `POST /test` sends one now; builder + text/html/push renderers in `server/digest.js` wrap `buildDigest`→`buildAgenda`. The push body lists the actual due items, not just counts; push + email carry a "see everything" link to the standalone page) · `digest-page` (mounted at **`/digest?token=…&cadence=&tz=`**, above the cookie gate, `widget_token`-authed like the widget feed — a self-contained styled HTML page with every reminder + graph orphans + Open-in-app / Insights links; `buildDigestPage` + `digestPageDoc` in `server/digest.js`; the notification and the email "see everything" link both point here) · `push` (Web Push subscribe, endpoint SSRF-validated; VAPID keys in `data/vapid.json`; send logic in `webpush.js`) · `widget` (read-only feed, token-authed; `?mode=agenda&tz=` returns `buildAgenda` output with deep-link URLs) · `history` (undo/redo log; `history.js` records entries from other routes, `routes/history.js` reverses them).
- `server/alarm-scheduler.js`: 30s `setInterval` from `index.js`; for each `reminders` row whose due instant (`COALESCE(snooze_until, next_at)`) has passed and hasn't been pushed, sends one Web Push and stamps `pushed_at`. The client rolls `next_at` forward (and clears `pushed_at`) on every poll while open — so a recurring reminder only stays armed for closed-app delivery if the app is opened between rings.
- `server/digest-scheduler.js`: 5-min `setInterval` from `index.js`; for each user with `digest_cadence` daily/weekly whose local hour (in `digest_tz`) matches `digest_hour` and whose cadence window has elapsed since `digest_last_sent_at`, builds the digest — skips if empty (no stamp, so a later tick that hour can still send) — then null-safe compare-and-sets `digest_last_sent_at` (one delivery wins the race) and sends via `digest_channel`. Push = deep link to `/`; email via `server/mailer.js`.
- `public/app.js`: `render()` draws the grid; `goTo()`/`jumpTo()` navigate + `logNav()`; centered note is **read-only**, click opens the fullscreen editor (`buildNoteEditor`); `attachCardDrag`→`rehomeCard` drags a card's link from center to another card (Android via Pointer Events); `🎨` colour toggle, `📊` insights, `🔔` agenda (client-side "what's due" over every reminder — overdue/today/this week/later buckets from the `alarms` array in the viewer's TZ; badge = triggered count; rows Open/Snooze/✓; `buildSnoozeSelect` shared with the ring popup; an "Open tasks" section is fetched from `GET /api/agenda` since the client note cache has no `content`). `👤` account overlay also holds the **digest** settings (cadence / hour / channel selects + "Send one now"), which `PUT /api/digest/prefs` on change and call `enableAlarmDelivery()` when a push channel is turned on. `init()` → `handleDeepLink()` consumes `/?d=agenda` / `/?d=insights` (used by the digest page's buttons) to open that overlay then strip the param. The `api.*` object is the single choke point for all server I/O: read methods write-through to IndexedDB and fall back to it; mutating methods (notes, links, reminders, nav) run the online→server / HTTP-error→throw / offline-or-drop→optimistic+`enqueue` pattern. The write-queue block (`outbox`/`flushOutbox`/`sendEntry`/`remapId`/`enqueue` coalescing/`handleConflict`/`openSyncPanel`) sits just after `syncLinks`.
- Markdown: `content` is GFM markdown, rendered via vendored `public/vendor/marked.min.js` + `purify.min.js` (`renderMarkdownInto`); `[[Title]]`/`[[#id]]` wikilinks resolve against `allNotesCache` (a marked inline extension) and navigate on click; task checkboxes toggle and write back through `toggleTaskInSource` + `PUT /api/notes/:id`. Editor has a Preview toggle; the textarea has `[[` autocomplete (`attachWikiAutocomplete`) that also creates the graph link.
- Search: `GET /api/notes/search?q=` over FTS5 (`notes_fts` external-content table + triggers in `db.js`, one-time `'rebuild'` gated by `PRAGMA user_version`). Topbar does an instant local title filter then swaps in debounced server results.
- `public/style.css`: phone type scale lives only in the shared `@media (max-width:640px), (max-height:500px)` block — keep `font-size` out of the per-orientation blocks.
- `public/sw.js`: PWA install + **shell precache** (stale-while-revalidate; `CACHE_VERSION` const; `/api`,`/uploads`,`/share`,`/digest` never intercepted — app.js owns their offline behaviour) + push delivery. On a new worker it posts `sw-activated` → app shows a "reload for the new version" toast. Alarm pushes carry `reminderId` + two "Snooze 10m/1h" action buttons; the worker POSTs `/api/alarms/:id/snooze` itself (fixed `now + N`, no TZ needed) and re-shows the notification if that fetch fails. A `type:'digest'` push shows the item list and opens its `url` (the `/digest?token=…` page) on click.
- `public/vendor/`: `marked`/`purify` **and now `leaflet.min.{js,css}` + `images/`** are vendored (Leaflet was CDN) so the map UI works offline; map tiles still need a connection.
